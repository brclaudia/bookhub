# ADR — Architecture Decision Records

Registro das decisões relevantes do BookHub: o que foi escolhido, por quê e quais alternativas foram deixadas de lado.

Um ADR não se apaga. Se a decisão mudar, o registro antigo fica como substituído e um novo ADR aponta para ele.

## Quando criar um ADR

- Escolha de stack, banco, autenticação ou hospedagem.
- Mudança de modelo de dados que afete o restante do sistema.
- Trade-off que outra pessoa precisaria entender depois.

## Modelo

Copie o bloco abaixo para um arquivo `NNNN-titulo-curto.md` (exemplo: `0001-persistencia-do-acervo.md`).

```md
# NNNN — Título da decisão

- Status: proposto | aceito | substituído
- Data: AAAA-MM-DD
- Substitui: — 
- Substituído por: —

## Contexto

Qual problema esta decisão resolve.

## Decisão

O que foi escolhido.

## Consequências

O que fica mais simples e o que fica mais difícil a partir daqui.

## Alternativas consideradas

- Alternativa A — por que não foi escolhida.
```
